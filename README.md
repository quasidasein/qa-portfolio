Привет! В этом репозитории собраны артефакты моей практики в тестировании ПО. Я фокусируюсь на исследовании логики продуктов, клиент-серверном взаимодействии, валидации API и создании качественной тестовой документации.

## 📁 Практические кейсы и артефакты

### 🎵 1. Автоматизация и контрактное тестирование API (Spotify Web API & CI/CD)
* **Формат:** Отдельный репозиторий с Postman-коллекцией, CI/CD пайплайном и зафиксированными дефектами спецификации.
* **Стек:** Postman, Newman (CLI Runner), GitHub Actions, Ubuntu Linux, REST API, OAuth 2.0 (Client Credentials Flow), JavaScript (Chai Assertion Library), JSON Schema.
* **Что реализовано:**
  * **CI/CD Пайплайн:** Настроен автоматический запуск тестов в headless-режиме через Newman на виртуальной машине Ubuntu Latest при каждом `push` и `pull_request` в ветку `main`.
  * **Security First:** Спроектирована безопасная архитектура. Ключи приложения изолированы через GitHub Repository Secrets (`SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`), а публичный экспорт коллекции содержит только плейсхолдеры.
  * **Request Chaining:** Написан Post-response скрипт для динамического парсинга и сохранения Bearer-токена в переменные коллекции (TTL: 3600 сек).
  * **Тест-дизайн и BVA:** Покрыты позитивные и негативные сценарии (400, 401, 403 Forbidden, 404). Проведено граничное тестирование пагинации (`limit`, `offset`) и обработка невалидных параметров.
  * **Contract Testing & Schema Validation:** Валидация структуры ответов, типов данных и строгая проверка Enums.
  * **Выявление Contract Drift:** Обнаружены и задокументированы расхождения между официальной документацией Spotify и реальным поведением бэкенда (депрекейт обязательных полей, противоречия в диапазонах `limit`).
* **Смотреть проект:** https://github.com/quasidasein/spotify-api-postman-suite

* **Формат:** Exploratory Testing (исследовательское тестирование) с сессионной видеозаписью процесса и анализом требований.
* **Описание:** Проведен аудит сервиса онлайн-записи. Применены техники тест-дизайна (BVA). Выявлены критические ошибки валидации полей, приводящие к серверным сбоям (статусы 500 и 400).
* **Материалы кейса:** Видеосессия (26 мин), баг-репорты и документация
