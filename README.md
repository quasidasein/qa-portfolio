Привет! В этом репозитории собраны артефакты моей практики в ручном тестировании. Я фокусируюсь на исследовании логики продуктов, клиент-серверном взаимодействии и создании качественной тестовой документации.

## 📁 Практические кейсы и артефакты

### 🎵 1. Тестирование и автоматизация API в Postman (Spotify Web API)
* **Формат:** Отдельный репозиторий с Postman-коллекцией и технической документацией.
* **Стек:** Postman, REST API, OAuth 2.0, JavaScript (Post-response scripts), JSON.
* **Что реализовано:**
  * **Security First:** Спроектирована безопасная архитектура хранения учетных данных. Секретные ключи (`client_id`, `client_secret`) вынесены в локальные переменные, изолированные от публичного экспорта (разделение Shared / Current Value).
  * **Request Chaining:** Написаны JS-скрипты для автоматического перехвата токена авторизации и записи в переменные коллекции, исключающие ручное обновление Bearer-токена.
  * **Управление окружением:** Реализована динамическая маршрутизация через переменные `{{base_url}}` и `{{auth_url}}`.
* **Смотреть проект:** [Ссылка на репозиторий spotify-api-postman-suite]https://github.com/quasidasein/spotify-api-postman-suite

### 📱 2. Исследовательское тестирование Telegram Mini App (BookingMaster / MastApp)
* **Формат:** Exploratory Testing (исследовательское тестирование) с сессионной видеозаписью процесса и анализом требований.
* **Описание:** Проведен аудит сервиса онлайн-записи. Применены техники тест-дизайна (BVA). Выявлены критические ошибки валидации полей, приводящие к серверным сбоям (статусы 500 и 400).
* **Материалы кейса:** [Видеосессия (26 мин), баг-репорты и документация](https://drive.google.com/drive/folders/1_b4I_qJr2xBw-EhkCibdFBeSD09ouFvy?usp=sharing)

### 📝 3. Тестовая документация: Web-регистрация (TuneCore)
* **Описание:** Проектирование тестовой документации (Test Design) для модуля регистрации веб-сервиса музыкальной дистрибуции.
* **Артефакты:** 
  * Набор из 15 атомарных **Test Cases** с детальным описанием шагов, тестовых данных, pre-conditions и ожидаемых результатов. Покрыты позитивные и негативные сценарии (анализ границ паролей, валидация email, reCAPTCHA, подтверждение пароля).
  * **Checklist** проверок формы регистрации с декомпозицией по полям и разделением на Positive/Negative проверки.
* **Смотреть артефакт:** [Чек-лист и тест-кейс.xlsx](./Чек-лист%20и%20тест-кейс.xlsx)

### 🎛️ 4. Тестирование Hardware: Mind Map (Behringer UMC22)
* **Описание:** Декомпозиция USB-аудиоинтерфейса. Составлена подробная карта проверок с учетом специфики оборудования.
* **Виды тестирования:** Functional (маршрутизация, latency, фантомное питание), Compatibility, Reliability, Stress-testing (экстремальные нагрузки), GUI & Usability.
* **Смотреть артефакт:** [Mind Map.pdf](./Mind%20Map.pdf)

### 💾 5. Практика работы с базами данных (SQL)
* **Описание:** Написание сложных запросов к реляционным базам данных для решения классических QA-задач (поиск аномалий, проверка связей).
* **Стек и конструкции:** `INNER JOIN`, `LEFT JOIN` (поиск потерянных записей через `IS NULL`), вложенные подзапросы (Subqueries), агрегатные функции (`COUNT`, `SUM`, `AVG`), группировка (`GROUP BY`) и фильтрация групп (`HAVING`).
* **Смотреть артефакт:** [sql-queries.sql](./sql-queries.sql)

### 🌐 6. Тестирование API (Postman & REST)
* **Файл:** `Petstore_API_Practice.postman_collection.json`
* **Стек:** Postman, JavaScript (Post-response scripts), REST API, JSON.
* **Что реализовано:**
  * Покрытие CRUD-операций для сущностей `User` и `Pet` (Swagger Petstore).
  * Динамическая авторизация (`Request Chaining`): автоматический парсинг токена сессии из ответа `/user/login` и передача в переменные коллекции.
  * Валидация статус-кодов (200, 201, 204), проверка структуры ответов (JSON schema) и бизнес-логики.
